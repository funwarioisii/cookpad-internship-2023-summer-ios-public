# 入力を保存し、一覧と詳細に反映する

Chapter 6では、入力したハッシュタグをサーバーへ送信しました。2026年版では、通信の成功だけでなく、待ち時間や失敗も含めて画面の動きを作ります。タグを追加すると、詳細と一覧の両方に表示されるようにします。

## 保存ボタンを押した後の動きを決める

まず、利用者の操作に沿って完成後の動きを確認しましょう。

1. 詳細画面の「#」ボタンから、タグの入力画面を開きます。
2. 全角の「＃」とスペースを半角に揃え、前後の空白や改行を取り除きます。空の入力は送信しません。
3. 保存を始めたら、完了するまで入力の編集、再送信、画面を閉じる操作をできなくします。
4. 保存に失敗したら入力を残し、エラーメッセージを表示します。同じ入力で再試行できます。
5. 保存に成功したら入力画面を閉じ、追加したタグを詳細と一覧に表示します。

2023年版では成功をアラートで伝えていました。完成サンプルでは、追加したタグが表示されることで結果を確認できるようにしています。

## 入力欄とモデルをつなぐ

入力内容と保存の状況は、[AddRecipeHashtagsViewModel](../../MiniCookpad/View/AddRecipeHashtags/AddRecipeHashtagsViewModel.swift) に持たせます。Viewでは、このモデルを `@State` で保持します。

入力欄へ値を渡すときは、`body` の中で `@Bindable` を使ってBindingを作ります。

```swift
@Bindable var model = viewModel
TextField("#タグ1 #タグ2（スペース区切り）", text: $model.text, axis: .vertical)
```

`$model.text` を通じて、入力内容がモデルの `text` に書き戻されます。モデルの保持とBindingの役割については [Observationの説明](state.md) も参照してください。

画面は `Form` と `Section` で組み立てます。キーボードが表示されたときや文字を大きくしたときも、内容をスクロールして操作できるようにするためです。

## 保存中の二重送信を防ぐ

ボタンから非同期の保存処理を呼び出し、成功した場合だけ画面を閉じます。

```swift
Task {
    if await viewModel.save() {
        dismiss()
    }
}
```

Viewでは保存中のボタンを無効にします。さらに、モデルの `save()` でも `canSave` を確認します。ボタン以外から呼び出されても、入力が空の場合や保存中の場合は送信しないためです。保存中を表す `isSaving` は、最初の `await` より前に `true` にします。

この教材では、一度始めた保存は結果が返るまで待つ方針です。保存中はキャンセルボタンと、シートをスワイプして閉じる操作を無効にしています。ボタン内で作った `Task` は、Viewが消えたことによって自動でキャンセルされるものではありません。ただし、アプリを終了した後も保存を続ける仕組みではありません。

通信が途切れても、サーバーではすでに保存が終わっている場合があります。画面内の二重タップを防ぐだけでは、再試行による重複まで防げません。実サービスに広げる場合は、同じ保存要求を受け取っても重複して登録しない仕組みを、サーバー側と合わせて考えます。

## 保存したタグを両方の画面に表示する

POSTのレスポンスには、今回追加したタグが入っています。[RecipeStore](../../MiniCookpad/Library/RecipeStore.swift) はこれを既存のタグに追加し、同じIDがあれば置き換えます。レスポンスだけでタグ全体を置き換えると、以前からあったタグが消えてしまうためです。

一覧と詳細は、同じStoreにある `hashtagsByRecipeID` を表示に使っています。保存後にこのデータを変更すれば、Observationを通じて両方の表示が更新されます。各画面に「再取得してほしい」と通知したり、シートを閉じたときの `onAppear` に頼ったりする必要はありません。

## 取得と保存の順序が入れ替わったら

通信は、開始した順番に終わるとは限りません。次の順序になった場合を考えてみましょう。

1. タグ一覧の取得を始めます。
2. 取得が終わる前に、新しいタグの保存が成功します。
3. 最初の取得が終わり、新しいタグを含まない結果が返ってきます。

最後の結果でStoreを上書きすると、保存したばかりのタグが画面から消えてしまいます。

そこでStoreは、レシピごとに更新回数を記録しています。保存に成功したら回数を増やし、取得開始時と結果を受け取ったときの回数を比べます。その間に保存が行われていれば、取得したタグでは上書きしません。

`@MainActor` を付けていても、この確認は必要です。`await` で通信を待つ間には、別の操作を実行できるからです。この仕組みが防ぐのは、同じStore内で取得と保存が重なる場合の上書きです。他の端末との同期まで解決するものではありません。

## 確かめてみよう

- `＃夕食　＃簡単` と入力し、全角の記号やスペースを含んでいても保存できることを確認しましょう。
- タグを追加してから一覧へ戻り、再び詳細を開いてみましょう。再読み込みをしても、追加したタグが残ることを確認してください。
- 保存に失敗する通信クライアントに差し替え、入力が残っていることと再試行できることを確かめましょう。
- [Chapter 7](../chapter_07.md) では、取得と保存の順序が入れ替わる場合をテストします。
